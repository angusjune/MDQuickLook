# Themes installed from `author/repo` codeload zips with a layout heuristic

A Theme Repo is fetched as `https://codeload.github.com/<author>/<repo>/zip/<branch>` — the same mechanism theme.typora.io's own Download links use. The installer scans the zip for `*.css` at depth 0–1 (repos differ: CSS at root like `blinkfox/typora-vue-theme`, or under `themes/` like `typora/typora-default-themes`); **each CSS becomes one Theme** (so `vue.css` + `vue-dark.css` install as two Themes, Typora parity), and everything adjacent to a chosen CSS (asset folders, fonts) is copied with it. Installed Themes are namespaced by repo (`<author>-<repo>/`) inside the App Group container shared by app and extension, so they cannot collide with each other or with the five Built-in Themes vendored in the app bundle (sourced from `typora/typora-default-themes`).

Rejected alternatives: the GitHub REST API (unauthenticated rate limits; branch resolved via codeload's `zip/HEAD`), shelling out to `git clone` (heavier), and scraping theme.typora.io (no machine-readable index; HTML gallery only).

**Amendment (M2):** installed Themes are stored in the preview extension's sandbox container (`~/Library/Containers/com.angusjune.MDQuickLookPreview/Data/Library/Application Support/MDQuickLook/Themes/<author>-<repo>/`), not an App Group container: ad-hoc signing cannot provision App Group entitlements, and PlugInKit hard-requires sandboxed QuickLook plug-ins. The unsandboxed Theme Manager app writes into the extension's container directly.
